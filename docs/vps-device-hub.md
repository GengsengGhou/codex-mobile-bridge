# VPS 统一入口与设备配对方案

状态：已实现并完成受控部署验收。下文使用 `https://codex.example.com` 作为示例地址，自行部署时替换为自己的域名。

## 使用目标

部署者有 VPS 和域名，最终用户无需自己的域名、VPS 或公网 IP。用户在手机浏览器登录统一入口，只能选择自己绑定的电脑，继续该电脑上的 Codex 会话。电脑须已开机、联网，Codex 与连接器须运行。

入口为 `https://codex.example.com`，Cloudflare DNS-only A 记录指向 VPS，原有 Caddy 提供 HTTPS。应用独立验证账号与设备归属。

## 连接结构

```text
手机浏览器 --HTTPS--> VPS：登录、设备列表、鉴权与请求转发
                         ^
                         | 每台电脑主动建立经过认证的 WSS 连接
                         |
                  电脑连接器 --> 本机桥接 --> 已运行的 Codex
```

电脑不需要公网端口，不要求用户配置路由器。VPS 是受信任的中转方，能处理经过它的请求与内容；本方案不是端到端加密。默认不将聊天正文和文件内容持久化在 VPS，账号、设备归属、必要操作元数据需要持久化。

## 配对与日常操作

1. 用户在统一入口登录；注册必须使用管理员签发的邀请，不开放公众无邀请注册。
2. 登录用户点击“添加设备”，获得有有效期、限流、一次性使用的配对码。
3. 用户在电脑上安装连接器，填写入口地址、配对码和设备名称。
4. 服务器原子消费配对码，将新生成的设备 ID 绑定到发起配对的账号，签发独立设备凭据。客户端不能自行指定所属用户。
5. 连接器主动建立 WSS 连接，报告在线状态及桥接协议版本。每台设备分别保管凭据；用户可撤销丢失或不再使用的设备。
6. 手机登录后进入设备列表，选择设备进入其项目与会话。页面始终显示设备名称；离线时禁用写操作。

设备名称允许修改；路由依赖不可混淆的设备 ID，不依赖名称或本机 IP。个人账号可绑定多台电脑。账号密码用于网页登录，设备连接不保存账号密码。

## 与现有桥接的衔接

- 保留现有本机 `127.0.0.1:4317` 服务与独立临时访问模式；不把本机自动会话端口直接开放到公网。
- 新增连接器作为本机受信任适配层，显式白名单转发桥接业务能力，不提供任意目标地址、端口、shell 或桌面 RPC 转发。
- VPS 对每次 HTTP 请求和长连接都检查登录状态、设备归属与设备撤销状态；设备 ID 不是访问权限。
- 前端请求、浏览器缓存、草稿、文件与回执必须按设备 ID 和会话 ID 共同隔离。切换设备时取消旧请求并丢弃迟到响应。
- 沿用现有请求 ID 和回执查询。断线不自动重放聊天、审批、新建会话或附件提交；连接恢复后先查回执。离线期间不在服务器积压执行命令。
- 转发支持大小限制、超时、背压与取消，验证现有上传和下载上限；不把大文件完整缓存在 VPS 内存中。
- 设备连接凭据只允许该设备注册连接，不授予浏览其他设备的权限。协议版本不兼容时明确报告，不能误报为在线可操作。

## 部署交付

原生 Ubuntu 部署使用 systemd 服务、专用 codexhub 用户、独立 Node.js 运行时及 Caddy；Hub 只监听 `127.0.0.1:4319`，账号与凭据哈希保存在 SQLite。数据目录权限 0700，数据库 0600。操作步骤见 `native-vps-deployment.md`。Docker Compose 方案也已提供且配置验证通过，但没有运行本机容器验收。

部署向导需要入口域名、首次管理员初始化和持久化目录。首次管理员仅能通过服务器端一次性初始化建立，不能由公网访问者抢先认领；密码和设备密钥不写入仓库或安装脚本。

`npm run release:package` 生成服务器 tar.gz、Windows ZIP、Windows EXE 及 `SHA256SUMS`，均在 `dist/`。不包含 `.local`、数据库、设备密钥或验收工作文件。目前尚未发布 GitHub Release，请自行构建。普通用户只需入口地址和配对码；自行部署者提供自己的 VPS 和域名。升级应保留数据与设备归属，支持版本核对、失败回退和单独撤销设备。

## 分阶段验收

1. 本地模拟 VPS：账号登录、配对码单次消费、设备归属隔离、撤销与重连。
2. 两台独立模拟设备：选择与切换、同名设备、相同会话 ID、不串草稿与文件、旧响应丢弃、写请求不重放。
3. 接入真实本机桥接：只读会话与文件验证；聊天和审批变更使用单独授权的测试会话。
4. VPS 部署：TLS、固定域名、后台运行、持久化与备份；通过手机流量实际测试登录、选择设备及断线恢复。
5. 发布安装包：新用户从下载、配对到使用的完整流程；另一台真实电脑与账号交叉访问验证。

已通过模拟多账号隔离、真实本机桥接、真实 VPS HTTPS 登录与当前电脑持久 WSS 连接。公网前端验收用真实页面模块在 jsdom 中执行，仅发 GET，没有聊天或审批变更。真实手机流量、触摸与视觉、第二台实际电脑尚未验收，详细结果见 `verification.md`。

## Windows 首次安装与再次启动

解压 Windows ZIP，双击 `deploy/install-connector.cmd`。安装器优先使用已有 Node.js 22.16+；否则下载官方 Windows x64 Node.js，验证 SHA256，并保存在包内 `.local/tools`，不修改系统 PATH。包包含 ws，不需要 npm 下载运行依赖。

安装器先确认本机桥接和 Codex 桌面已连接。若没有已有桥接，会让用户从本机普通会话中明确选择启动身份；桌面离线或身份有歧义时停止，不消费配对码。然后输入配对码，设备凭据以 Windows 私有 ACL 保存到 `.local/hub-connector.json`，账号密码不落盘。连接器提交后台启动后，应在 Hub 核对在线状态。

安装成功后会注册当前用户独立命名的 Windows 登录任务（交互用户、不提升权限、登录后延迟 10 秒）和登录启动项，恢复已保存的本机桥接，再启动连接器；Codex 尚未打开时会等待，不重新配对或选择会话。两种触发使用同一互斥锁，只运行一个恢复监测。只修改本安装目录拥有的任务与启动项，遇到同名外部命令会拒绝覆盖。任务与启动项只存隐藏脚本路径，包内另保存非敏感 Node 路径，不存账号密码或设备令牌。后台连接器独立于安装终端运行。

电脑重启后仍需用户登录 Windows 并打开 Codex；不会自动开启 Codex，不提供登录前控制、睡眠唤醒或断电恢复。登录脚本将恢复监测提交给独立 WMI 进程，每 10 秒检查保存端口和连接器心跳，重试临时启动失败并恢复退出的进程；已有离线连接器继续自行重连，不反复启动。启动脚本诊断记录在 `.local/connector-login-bootstrap.log`，监测日志在 `.local/connector-login.stdout.log` / `.stderr.log`，连接器状态在 `.local/hub-connector-state.json`。Windows 禁用启动项、保存配置损坏或 Node 路径失效仍需本机修复。安装目录或 Node 路径移动后须重新运行安装器。可手动运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/connector-login.ps1` 恢复完整监测。已有绑定若属于其他入口或桥接端口，会拒绝自动覆盖，先停止旧连接器并在原账号撤销设备后重新配置。
