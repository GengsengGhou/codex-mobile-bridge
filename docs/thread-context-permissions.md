# 会话上下文、权限与待处理交互

## 入口与状态

对话上方的右栏图标打开“会话上下文”。桌面显示右侧列，手机显示可关闭的侧边面板；默认收起。切换会话时清除旧上下文，取消旧读取并忽略迟到响应。连接中断时明确标记信息暂不可用，不能把上次读取的权限当作当前确认值。

右栏默认展示当前权限、简洁工作目录与 Git 状态，以及活动子智能体。已完成子智能体和“来源”默认折叠并显示数量；完整路径、提交哈希和技术名称放在详情或提示中。折叠不改变真正待处理问题、当前权限或可行动状态。Git 查询只读当前会话目录；没有仓库或读取失败时显示不可用。

点击可读取的子智能体会打开独立只读查看器，支持刷新、历史分页和关闭返回，工作过程默认折叠。查看器不会切换主会话、主地址、草稿、阅读位置或普通侧栏，也没有发送、重命名、置顶或归档入口。刷新保留已载入历史、阅读位置和详情展开状态；迟到响应、关闭和登录失效均受隔离保护。子智能体中的本地文件引用只显示文本，避免打开主会话目录。

代理名称、路径和状态来自桌面记录与会话读取，嵌套关系用于缩进。普通侧栏只移除已由稳定 ID 或明确代理元数据确认的子智能体，保留真正未命名的普通会话。旧的子智能体地址和缺少元数据的缓存行会先读取身份，再打开查看器；读取身份期间暂时禁用发送，草稿仍可编辑。明确的完成事件在原生状态为“空闲”或“尚未载入”时继续保留；新的运行状态优先，不把所有空闲会话猜成完成。

“来源”是桌面界面中的信息来源，包括附件文件、已识别网页、网页搜索和工具调用名称，不是会话的创建来源，也不是代码知识图谱。当前仅汇总已载入历史内可识别的记录，不能视为完整检索结果或全部引用。只展示经过归一化的名称、文件路径与安全网页地址，不显示任意工具参数、结果正文或原始桌面状态。来源文件使用既有文件预览入口及目录权限检查；网页在新页打开。

## 下一轮权限

输入区的“权限 · 沿用桌面”菜单提供桌面确认支持的“完全访问”和“请求批准”。默认选择省略 `permissionMode`，继承桌面配置。显式选择随下一轮发送请求提交，不修改已经运行的一轮，也不写入桌面的全局默认设置。

选择和模型设置一样，按当前认证账号、设备和会话保存到浏览器会话存储。后续新轮次继续使用这个选择，直到恢复“沿用桌面”。运行中补充显示“下轮权限”，只补充当前轮次并省略权限覆盖；选择保留到下一轮。发送前任务如果已开始运行，服务端拒绝显式覆盖，草稿保留，不自动重发。

权限目录来自 `GET /api/status` 的 `permissionOptions.send`。消息请求只接受 `full-access` 或 `request-approval`，无效值明确拒绝；不支持原生覆盖时返回 `PERMISSION_UNAVAILABLE`，运行中覆盖返回 `PERMISSION_CHANGE_ACTIVE`。显式权限参与请求指纹，同一请求 ID 改变权限会产生冲突。旧桥接端不提供权限目录时，只能继承桌面；已保存的显式选择阻止新轮次发送，必须先重新选择，不能悄悄忽略。

新建会话目前没有经过验证的原生权限覆盖参数，因此 `permissionOptions.create` 为空，创建表单不提供权限选择。权限读取与发送受既有发送范围、账号、设备和本机会话约束；桌面接口升级后不能识别时明确返回不可用。

显式权限通过所属桌面实例的原生启动路径发送。发送会先核对会话所属实例、空闲状态、工作目录与当前设置，保存请求记录后再次读取最新快照，验证一致后构造并写入请求。确认未投递的变化拒绝会释放记录，投递结果未知则保留记录供回执核对。仅覆盖权限时继续继承已有模型、协作模式和自定义指令；同时显式选模型时按桌面的 `collaborationMode.settings` 传递模型与强度，不能仅凭顶层 `params.model` / `effort` 为 `null` 判定设置丢失。

当前桌面接口不提供原子的检查并启动操作。最后一次快照核对之后，如果桌面恰好立即启动另一个任务，仍有未消除的竞态；因此该行为是实验性适配，不能承诺未来接口或所有并发场景都兼容。它不改变运行中补充省略覆盖、结果未知不重试的边界。

## 问题折叠与关闭

真正待处理的交互默认显示紧凑入口，点击后展开命令、差异或问题。长问题在正文区域内滚动，提交按钮保持可见。收起只改变显示，保留请求状态和非敏感回答草稿；按账号、设备和会话保存展开选择，刷新、轮询和会话切换不会重新撑开已收起的面板。新请求可以显示“新”提示，已查看的旧请求不重复提示。

已明确属于旧轮次的不可行动问题进入默认折叠的“任务详情 / 历史提问”，不计入待处理数量。历史提问可关闭，再通过“查看历史提问”恢复；关闭状态针对同一批历史记录保存。控制快照暂时不可用时保留现有待处理入口与内容，并禁止回复；断线不会把仍需处理的请求误判为历史。

聊天缓存使用桌面稳定消息 ID 处理轮次归属变化。最新快照中的消息移到新轮次后，旧缓存位置会被移除；迟到历史页不能把它放回旧位置。同文且不同消息 ID 的两次有意发送继续显示。消息匹配只影响乐观气泡显示，发送回执仍按请求 ID 核对，不能用同文消息证明未知发送已接收。

## 验证边界

运行状态与上下文的补充读取使用新鲜的会话元数据（`read_thread`、`turnLimit: 1`、`includeOutputs: false`），子智能体状态也使用同一路径，避免为身份、目录和状态传输工具输出与聊天正文。正文历史仍使用原有读取接口。并发的状态和上下文请求只共享正在进行的元数据与原生快照读取，完成后立即移除；发送和其他写入操作继续执行自己的新鲜预检。

原生找不到所属实例且会话元数据为 `notLoaded` 时，接口返回明确的待命状态，停止按钮不可用。已经载入的会话缺少所属实例、原生断连或超时仍属于读取失败。不可用响应的 `nativeReason` 仅允许固定的协议原因名称，不包含原生错误正文或业务内容；它用于诊断，不能据此猜测运行状态或当前权限。

前端回归测试覆盖默认省略覆盖、运行中补充、旧端拒绝、账号设备会话隔离、迟到上下文、嵌套代理、安全文本、历史迁移与关闭、问题草稿、稳定消息迁移和有意重复发送；子智能体查看还覆盖主会话隔离、真实未命名会话保留、旧缓存身份确认、取消迟到读取、只读分页刷新、详情与焦点恢复及退出登录清空。隔离浏览器验收使用真实 Chromium 与模拟 HTML/API，覆盖桌面、390 像素和 320 像素宽度。模拟权限和问题不代表实际执行了命令、作业或审批；实体手机触摸与未来桌面版本兼容性不在该验收范围。
