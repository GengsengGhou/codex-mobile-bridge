# 简易配置教程

用手机浏览器继续电脑上的 Codex 会话。电脑需要开机、联网，用户已登录 Windows，Codex 桌面已打开；连接器不会自动开启 Codex，也不能唤醒睡眠或断电的电脑。

本项目是非官方客户端，依赖 Codex 桌面的内部接口；桌面升级可能要求更新适配。服务运营者能处理经过 VPS 的请求和内容，当前方案不是端到端加密。仅在你信任的服务上登录和配对。

## 选择接入方式

| 接入方式 | 谁准备服务器 | 谁给你入口与账号 |
| --- | --- | --- |
| 自己部署 | 你准备 Ubuntu / Debian VPS 和可用域名 | 部署后在服务器初始化管理员；普通账号使用管理员邀请 |
| 受邀使用已有服务 | 服务管理员 | 管理员私下发入口网址和一次性邀请；你注册自己的账号 |

自己部署请先完成 [原生 VPS 教程](native-vps-deployment.md)，或选择 [Docker Compose 教程](compose-deployment.md)。两种部署方式择一。服务器准备好后，继续本页的电脑配对。

## 下载与校验

稳定版为 v1.0.2。请从 [最新稳定版 Release](https://github.com/GengsengGhou/codex-mobile-bridge/releases/latest) 下载所需文件和同一版本的 `SHA256SUMS`：

| 文件 | 用途 |
| --- | --- |
| [CodexMobileConnector-Setup.exe](https://github.com/GengsengGhou/codex-mobile-bridge/releases/latest/download/CodexMobileConnector-Setup.exe) | Windows x64 图形安装器，普通用户优先使用；内置 Node.js 和连接依赖 |
| [codex-mobile-connector-windows.zip](https://github.com/GengsengGhou/codex-mobile-bridge/releases/latest/download/codex-mobile-connector-windows.zip) | Windows 终端安装备用包 |
| [codex-device-hub.tar.gz](https://github.com/GengsengGhou/codex-mobile-bridge/releases/latest/download/codex-device-hub.tar.gz) | VPS 服务及部署脚本 |
| [SHA256SUMS](https://github.com/GengsengGhou/codex-mobile-bridge/releases/latest/download/SHA256SUMS) | 三个安装产物的 SHA-256 清单 |

公开仓库与 Release 可直接下载，不需要 GitHub 令牌。下载源码或安装包不会授予任何桥接账号；使用已有服务仍需管理员私下提供入口和邀请。不要把实际入口、邀请或配对码放进公开 issue 或截图。

Windows 中在下载目录打开 PowerShell：

```powershell
Get-FileHash .\CodexMobileConnector-Setup.exe -Algorithm SHA256
Get-Content .\SHA256SUMS
```

把计算结果与同一 Release 清单中同名文件的完整 64 位哈希比较，字母大小写不影响比较；不一致时停止安装并重新下载。EXE 尚未进行代码签名，Windows 可能显示未知发布者或信誉提示，SHA 校验不能替代代码签名。

## 受邀使用已有服务

1. 向服务管理员私下获取 **HTTPS 入口网址** 和 **一次性邀请链接或邀请码**。入口应形如 `https://codex.example.com`；这里是示例，不能直接用于登录。运营者真实网址不写进源码，但受邀用户必须知道这个网址才能连接。
2. 在浏览器打开邀请链接，会直接进入“邀请注册”；若只收到邀请码，打开入口，点击“使用邀请注册”。设置自己的账户名和密码。账户名为 3 至 64 个字母、数字或 `._-`，按小写保存；建议使用至少 12 个 ASCII 字符的独立密码。
3. 邀请在生成后 24 小时到期，成功注册后即失效，只能创建一个普通账号。过期或已使用时请管理员重新生成；已有账号直接登录，不要重复注册。
4. 登录后进入“我的设备”。接下来生成的是电脑 **配对码**，不是注册邀请。

## 配对 Windows 电脑

1. 双击已校验的 `CodexMobileConnector-Setup.exe`，在安装界面选择中文或 English，再安装到当前 Windows 用户，不需要管理员权限或手动安装 Node.js。首次安装使用默认用户目录即可。安装或升级后，桌面和开始菜单都有“Codex Mobile Bridge”快捷方式；按 Windows 键搜索“Codex Mobile Bridge”即可再次打开。删除桌面快捷方式后，普通启动不会重新创建。
2. 在连接器填写管理员提供的 HTTPS 服务器地址，点击“打开网页登录”。已有账号直接登录；新用户点击“使用邀请注册”，填写管理员的邀请码并设置自己的账户名和密码。
3. 登录后，在网页的添加设备入口填写设备名称，例如“办公室电脑”，点击“生成配对码”。配对码在生成后 10 分钟到期，只能绑定一次。每个账号最多绑定 10 台设备；同时最多保留 3 个未过期配对码。
4. 点击“复制配对码”，回到电脑连接器填写设备名称、粘贴配对码并绑定。也可以使用网页的“复制配对信息”快捷填入服务器、名称和配对码；其中的 JSON 同样含一次性凭据，按机密信息处理。账号密码与邀请码只在网页输入，不填入连接器。
5. 打开 Codex 桌面，确保已有一个普通本机会话。连接器可先配对再等待 Codex；它会只读识别可用会话，不会为了初始化而创建会话或发送消息。首次识别完成后，在网页点击“刷新”，确认设备在线。
6. 手机上打开同一个入口，登录自己的账号，在设备列表点击“打开会话”。先核对电脑名称、会话标题与工作目录，再发送消息。离线时请先恢复电脑连接，结果未知的提交不会自动重发。

| 名称 | 用途 | 有效期 |
| --- | --- | --- |
| 邀请链接 / 邀请码 | 注册一个普通账号 | 24 小时，一次性 |
| 配对码 | 把一台电脑绑定到当前网页账号 | 10 分钟，一次性 |
| 账号密码 | 网页登录 | 不是配对码，不填入安装器 |

首次成功配对会默认开启当前 Windows 用户的登录后自动连接，并立即在托盘后台等待 Codex。若此前已明确关闭该设置，首次配对会保留关闭状态。设备令牌只保存在电脑私有 ACL 保护的 `.local` 数据中，不上传 GitHub。

托盘显示“尚未绑定这台电脑”时，双击图标打开窗口，完成上面的 HTTPS 入口和配对码步骤。新安装目录不会自动继承另一个源码或 ZIP 目录里的设备配对；网页上原有设备在线，不代表新安装程序已经绑定。仍在使用原目录连接器时，可以继续使用那个设备，不必为它重新配对或复制私有凭据。

## 托盘与自动启动

- 点击窗口 X：隐藏到托盘，连接继续。双击托盘图标或点击托盘菜单“显示窗口”可恢复窗口。
- 连接与断开：托盘菜单“连接”明确恢复已保存配对；“断开连接”会暂停连接并跨 Windows 登录保留，之后只能再次明确点击“连接”恢复。
- 主动退出：点击托盘菜单“退出”，停止本安装的后台监测和连接器，手机上的电脑会离线。本次 Windows 登录内不会被后台自动拉起；下次 Windows 登录会按自动连接设置启动，除非此前已执行跨登录持久断开。独立桥接、Codex 及其任务不会停止，配对与配置继续保留。
- 再次使用：开始菜单打开窗口只显示状态，不会自行恢复连接；使用“连接”命令可恢复保存的配对并等待 Codex，无需重新配对。
- 登录后自动连接：首次成功配对默认开启“Windows 登录后自动连接”。若配对前已明确关闭该设置则继续保持关闭；窗口或托盘可随时更改。登录后应用隐藏到托盘并恢复监测；Codex 仍需自己打开。
- 关闭自动启动：只取消之后的 Windows 登录启动，不改变当前连接。主动退出也不改变已经开启的自动启动选择。

连接器默认自动检查最新稳定版，也可在设置页手动“检查更新”，或关闭“自动检查更新”。检查不会改变连接、配对或主动断开状态，也不会后台安装。发现新版时点击“下载并升级”，程序校验下载文件后打开安装器，由你确认升级；网络检查失败时仍可使用当前版本并稍后重试，或从 Release 下载 EXE。

运行更高版本安装器并点击“升级”，会原位更新应用并保留 `.local` 配对、自动连接设置和主动断开状态；相同或更旧版本会拒绝覆盖。旧 v0.1.0 卸载器会删除登录启动设置，因此保留配对重装后，重新核对、按需要勾选自动连接开关；不会从配对或身份标记猜测你曾选择的自动模式。安装目录和内置 Node 路径不要移动。详细安装、替换服务器、卸载与备用 ZIP 操作见 [Windows 安装说明](windows-installer.md)。

网页上的语言选择会保存，并在设备入口与会话页间共用；桌面软件也能从“设置 / Settings”切换。界面换语言会保留草稿，消息和文件内容保持原文，见 [语言说明](languages.md)。

## 管理员邀请别人

使用已初始化的管理员账号登录自己的入口，在“邀请账户”中点击“生成邀请”，再点击“复制邀请链接”。每位受邀者生成一个新邀请，通过私下渠道发送入口网址和该邀请；不要把它们放进 GitHub issue、截图、Release 说明或公开聊天。普通账号看不到此管理员入口，服务端也会拒绝普通账号生成邀请。

管理员的服务账号仍只能进入自己配对的设备。VPS 运营者具有服务器控制权，因此仍应被视为受信任方。移除设备会立即撤销其连接凭据；更换服务时应在原账号中移除旧设备。

## 常见问题

| 现象 | 检查 |
| --- | --- |
| Release 显示 404 或没有下载按钮 | 核对发行版本与链接，稍后刷新；下载权限与服务账号无关 |
| 邀请注册失败 | 核对入口、邀请码、用户名和密码；邀请是否过期或已使用；勿使用配对码注册 |
| 配对失败 | 核对安装器与网页是否使用同一个 HTTPS 入口；重新生成未过期配对码；勿粘贴邀请链接 |
| 连接器提示缺少 WebView2 | 按窗口入口安装微软 WebView2 Runtime，再重新打开连接器；通常 Windows 已自带，不需要单独安装 |
| 托盘显示尚未绑定，但网页已有设备在线 | 两者可能属于不同安装目录；在窗口完成新安装的配对，或继续使用原连接器，勿复制令牌合并设备 |
| 设备在线，但 Codex 不可用 | 打开 Codex，等待普通本机会话可用；检查连接器状态，桌面升级后内部接口可能不兼容 |
| 找不到已安装的应用 | 按 Windows 键搜索“Codex Mobile Bridge”，或双击桌面“Codex Mobile Bridge”；快捷方式被删除时可从 `%LOCALAPPDATA%\CodexMobileConnector\CodexMobileConnector.exe` 打开 |
| 设备离线 | 电脑是否开机、联网、已登录 Windows；连接器是否运行；服务器 HTTPS 是否可访问；窗口可查看状态并重试 |
| 重启后未恢复 | 确认已开启登录后自动连接、当前 Windows 用户已登录、没有主动断开连接，且安装目录及内置 Node 未移动 |
| 已提交但结果未知 | 先核对会话和回执，不要直接重复发送；网络恢复不会自动重放操作 |

实体手机触摸、第二台实际电脑及完整交互桌面的验收边界见 [验收摘要](verification.md)。VPS 健康检查、日志、备份与重启排错见 [部署教程](native-vps-deployment.md#健康检查与排错)。
