# 协议与兼容边界

连接器为 Codex Mobile Bridge 提供本机适配，读取 Codex 桌面会话并在用户授权范围内转发请求。它依赖 Codex 桌面随附的内部接口；这不是稳定的公开接口，桌面升级可能改变可用方法、字段或行为。

Codex CLI 的 App Server 文档和命令说明可以帮助理解协议概念，但不能证明某个桌面版本会暴露相同的传输端点、方法或权限。开发者应在目标桌面版本上验证具体行为，不要只根据 CLI schema 或过去的探查结果推断兼容性。

## 桌面入口发现

v3.0.0 在 Windows 自动识别严格 UUID 名称的 `codex-app-tools-*` 与旧 `codex-browser-use-*` 管道。新入口优先探查，每批最多八个、每次目录探查超时一秒；超过 128 个候选时明确报告入口过多，不截断后猜测桌面。工具目录必须同时提供 `codex_app.list_threads` 和 `codex_app.read_thread`。多个可用桌面时拒绝自动选择，可从目标桌面任务环境重新启动连接器以明确入口。

已选入口断开、拒绝或返回协议错误时，只读请求最多重新发现并重试一次；发送等写入请求不会自动重发。没有可用入口时短暂退避后允许后续请求重新发现。本次变更不修改 Hub 协议，现有 v2.0.1 Hub 可继续使用。

## 维护原则

- 新增读取能力时，校验响应形状、会话身份和分页游标，再更新页面状态。协议字段缺失或不匹配时返回可恢复错误，不显示成空会话。
- 对提交类请求使用稳定的请求 ID 与回执查询。超时、断线或响应丢失时先查原回执；结果未知时不自动创建新 ID 或重发。
- 遇到桌面不支持的能力时明确报告不可用。读取降级只用于明确的读取场景，不能改变发送、审批或创建语义。
- 不把原生异常正文、令牌、聊天内容或文件内容放进诊断响应和日志。通过固定错误类别传递必要信息。

## 验证方法

先用只读调用确认目标桌面、会话 ID、响应字段和权限状态。涉及消息发送、审批、创建、停止或文件写入时，使用专门的可丢弃测试会话并确认目标；中断后以原操作回执核对结果。开发检查命令见[开发验证指南](verification.md)。
