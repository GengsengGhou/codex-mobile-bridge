# 开发验证指南

开发和验证命令需要在完整 Git checkout 的仓库根目录执行。Windows 安装包面向运行时使用，不包含项目测试、构建和资源生成脚本，也不包含开发依赖。

## 基本检查

使用 Node.js 22.16 或更新版本安装依赖并执行自动化测试：

```powershell
npm ci
npm test
```

`npm test` 运行 `test/` 下的自动化用例。它验证本地实现，不等同于在目标电脑上完成 Codex 桌面、Hub、真实浏览器和手机的端到端使用。

## 有副作用的场景

需要验证桌面协议、实际会话或 Hub 部署时，使用专用账号、设备和可丢弃任务。发送消息、审批、停止任务、注册设备或更改服务状态都可能产生实际效果；执行前确认目标并记录清楚操作结果。对回执未知的提交先查询原操作，不要创建新请求重复派发。

开发过程中的脚本、日志、截图和临时证据只放在 Git 忽略位置或系统临时目录。不要把账号、设备令牌、邀请链接、配对码、聊天正文或私有配置放入仓库。

## 发布前检查

发行包通过 `npm run release:package` 构建到 `dist/`，命令和完整依赖必须来自源码仓库。构建结果应按对应平台核对文件清单与 SHA-256；服务端或 Windows 安装器的验证以各自部署文档列出的运行条件为准。自动化测试、隔离模拟与真实设备试用属于不同检查范围，应分别记录，不要把模拟结果描述成实体设备验证。
