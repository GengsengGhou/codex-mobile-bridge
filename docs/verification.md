本轮确认了磁盘升级后旧常驻 connector 仍保留旧协议路由表的生产回归：新 context 请求被旧进程拒绝并导致连接断开重连。精确刷新该项目 connector 后，现有实际本机桥接通过隔离、已鉴权的完整 HTTP/WebSocket relay 连续三轮读取 status（200、304、304）及 context/control（均 200 且可用），同一连接保持，无业务消息、审批或权限变更。网页回归覆盖迟到 304 不覆盖较新的离线状态、真实成功的 304 可恢复在线、桌面离线后读取历史不能伪造 Codex 已连接、繁忙和单一路由不支持不判设备离线，以及异常 POST/PUT/PATCH/DELETE 304 只调用一次并保留送达未知；实际页面 POST fixture 保留草稿和提交锁，直到只读回执恢复。升级必须同时核验常驻 connector、桥接 child 与 Hub 的已加载版本，详见 [native-vps-deployment.md](native-vps-deployment.md#数据库备份与升级)。

本轮新增 7 张隔离 headless Chromium 页面截图，覆盖 320、390 与桌面宽度下的在线、设备离线、等待 Codex 和路由不支持提示，没有脚本错误或横向溢出，且没有 mutation 请求。内置浏览器和已登录生产浏览器会话本轮不可用，没有提取浏览器 cookie 或额外登录；该隔离验收不能等同于用户原公网 Chrome 页面或实体手机验收。
