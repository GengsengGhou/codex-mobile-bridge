# 电脑协作

电脑协作需要各参与电脑运行兼容的连接器与 Hub，并使用同一 Hub 服务、同一账号配对且保持连接。管理员需部署支持电脑协作的 Hub。原有手机访问不需要开启电脑协作。

普通修复会保留本机配对和设置；主动重置会清除本安装的配对与协作授权，并按下文范围处理 Codex 配置。更换服务器或重新配对产生新设备身份后，来源和目标电脑都需明确重新保存相应授权。修复后重新打开 Codex 或重新加载协作连接。

## 使用流程

每次更换服务器流程中明确输入或已打开网页的目标地址会受到保护：粘贴其他服务器的完整配对信息时，保留当前目标和设备名称、清空配对码并提示来源不一致，不自动切回旧服务器。首次没有明确目标时仍可由完整信息填写服务器；取消后开始新的更换流程可重新导入。完整信息导入后手动改变服务器会清空原信息中的配对码，避免把该码用于另一入口。重新连接只恢复当前保存的身份；成功更换服务器后会清除旧的后台启动警告。后台监测每次按当前保存的服务器和设备身份核对心跳。

1. A、B 两台电脑均升级到 v2.0.0，使用同一个 Hub 服务和账号配对，并保持连接；两台电脑上的 Codex 桌面也需打开。
2. 在目标电脑 B 的“设置 > 电脑协作”中打开“允许其他电脑指挥本机”，选择来源电脑 A 和允许访问的本机项目，然后保存。来源设备和项目均需至少授权一项。
3. 在来源电脑 A 的同一设置页打开“本机 Codex 指挥其他电脑”，然后在 Codex 中重新加载连接，或关闭后重新打开 Codex。连接器会自动注册随安装包提供的 MCP 工具，无需另装项目、填写模型密钥或更换模型提供方。
4. 在 A 的 Codex 中明确指定 B、项目和工作，例如“列出 B 上允许协作的项目，在项目 X 新建任务检查……”。工具返回 B 的原生桌面任务 ID；B 的用户可以在桌面继续接手。
5. 如需双向协作，在 A 允许 B 与项目，在 B 开启指挥功能。两个开关相互独立，可以离线关闭其中任意一项；关闭接收不会停止已经派发的 Codex 工作。

两个开关默认关闭且控制方向相互独立。需要双向协作时，在 A 授权 B 及项目，并在 B 打开指挥开关。模型、第三方提供方及 API 密钥始终沿用各台电脑的本机 Codex 设置。电脑协作仅限制可派发/读取的会话及文件接口；任务的实际执行权限、shell 可访问目录和审批由 B 的 Codex 配置管理，项目列表不是操作系统文件沙箱。协作工具不提供自动审批、权限提权、通用 HTTP 代理或远程任意路径写入；需要审批的运行返回 `needsAttention`，由已有桌面或手机入口处理。

## 授权与生命周期

Hub 使用已绑定的设备凭据认证 A，派生来源设备 ID，仅转发同一账号的目标电脑。来源请求正文不能填写或伪造来源身份；普通手机会话入口不能访问该协作通道。Hub 在传输帧处理时重新验证来源凭据、账号及目标设备。

B 的连接器每次重新读取绑定到确切 Hub 地址和本机设备 ID 的设置，并检查当前配对凭据。任务必须属于本机普通 Codex 会话、指定项目和匹配的工作目录；目录边界与链接/junction 检查在执行端实施，创建/发送/停止还在原桌面桥接的执行边界重新验证。重新配对或换服务器会使旧授权失效，需明确重新保存设置。

已有协作设置的电脑成功重新配对后，会关闭两项协作能力并清空旧电脑与项目选择，显示“需要重新授权”；首次配对且未配置协作时仍默认关闭，不要求启用。请刷新“电脑协作”页，确认当前服务器和账号，重新选择电脑与项目并明确保存。设备名称可以保持不变，但重新配对生成新的设备身份，目标电脑也需重新授权该来源。已有 Codex 配置和业务回执保留，不自动迁移权限。凭据已经保存但协作清理失败时会显示部分成功提示，不应重复使用已消费的配对码。

待重新授权时 MCP 返回 `COLLABORATION_BINDING_CHANGED`，保留连接以显示处理步骤；明确断开、退出、关闭协作、升级和卸载仍执行原有生命周期限制。`DEVICE_REVOKED` 是服务器不接受当前设备凭据的认证错误，可能由服务器不匹配、旧凭据、设备撤销或账号禁用导致，单独这一代码不能证明有人撤销了设备。两个错误需要分别处理。连接状态也将只接受与当前服务器和设备 ID 一致的心跳，不把旧进程在线状态归到新配对。

启用指挥功能的注册保存过程中，工具请求返回 `COLLABORATION_SETTINGS_PENDING`，不会派发任务或中断 MCP 连接；保存完成后可继续使用。注册失败时保留连接并返回原注册错误（例如 `MCP_REGISTRATION_CONFLICT`），指挥能力保持关闭，供用户核对设置后重试。明确关闭指挥或卸载仍关闭工具连接。

“所选电脑或项目已改变”只用于已成功刷新列表后找不到所选设备 ID 或项目路径的情况；目标电脑离线但仍在同账号设备列表中可以保存授权。项目列表暂时读取失败会单独提示尚未保存，保留原授权及当前选择，待 Codex 就绪后刷新重试。保存失败的设置页显示当前错误，不把已有 MCP 注册“已就绪”当作这次保存成功。刷新发现已消失的身份或路径时只清理未保存的选择，不按同名电脑自动替换或授权。

关闭指挥功能会先禁用工具使用，再移除本产品拥有且没有自定义工具设置的 Codex 配置。配置条目名称为 `codex_mobile_computer_collaboration`；只有有效所有权记录和解析后完全等价的设置才允许清理。CRLF、注释、引号表头或键顺序等格式变化不会误报冲突；第三方同名条目或 command、args、env、其他选项的实际变化仍保留原文并提示处理。关闭后即使配置清理发生冲突，工具也不可继续使用。

Codex 可在同名连接下增加 `tools` 工具设置，例如 `tools.collaboration_devices.approval_mode="approve"`。只有所有权记录完整且除受支持的 `tools` 设置外其余内容完全一致，才允许继续启用；保存不会改写 Codex 原文、更新所有权记录或重置单项工具限制，不必删除这些设置。兼容范围是官方 MCP 单项工具字段 `approval_mode`（`auto`、`prompt`、`writes` 或 `approve`）和 `output_token_limit`（正的安全整数）；不把应用工具的 `enabled` 字段套用于 MCP，也不自动接受顶层其他选项。关闭指挥时先关闭本机授权，完整保留带工具设置的连接和所有权记录；重新开启继续沿用这些限制。卸载也保留这些设置并明确提示，卸载后请在 Codex 设置中检查仍指向本应用的连接并手动移除。工具设置形状无法确认、未知键或启动内容改变时仍拒绝自动接管。

注册还核对自有连接的 MCP 脚本是否属于当前安装目录。复制旧安装的所有权记录可能使连接仍指向旧目录；此时保留 Codex 原文和配对，明确提示目录不一致。确认是本产品拥有且内容未改变、没有自定义工具设置的旧连接后，可关闭指挥并保存，再重新开启并保存，最后在 Codex 重新加载连接。带工具设置的旧连接仍完整保留，需先人工核对安装路径与工具限制；没有有效所有权记录或内容已改变时不会自动接管。这个步骤不修复 `DEVICE_REVOKED`：重新启用仍要求当前服务器接受设备凭据。

明确断开或退出连接器也暂停发起协作；MCP 读取现有连接暂停意图，并关闭本安装的工具进程。关闭窗口到托盘仍保留原有连接行为。

卸载先关闭两项能力、取消待重新授权和待注册状态并尝试精确移除自有注册。有效所有权记录下的区块实际内容已变时，保留 Codex 配置并提示手动删除同名连接；确认本安装进程均停止后可完成卸载。所有权记录损坏或缺失、中断事务、配置不可读取、锁定及进程未停止等错误仍停止卸载并保留安装。桌面卸载显示完成、保留配置警告或失败提示；命令行返回结构化结果。升级保留私有设置和注册，停止本安装目录中的 MCP 进程；升级日志存在时，新工具调用及接收都暂停。升级后在 Codex 中重新加载连接即可。

## 明确重置与诊断

设置页的“配置已注册”只表示本地 MCP 配置注册成功，不能证明 Codex 既有工具连接正常。遇到 `Transport closed` 或绑定不一致时，可以先“复制”诊断信息核对当前文件与安装。诊断不含设备令牌，当前文件与策略是否匹配会重新读取；它不把未知的现有 Codex 传输状态当作握手成功。页面所见 Hub 或设备 ID 变化时清空旧选择；保存也校验该身份，迟到的旧响应不会恢复旧授权草稿。

需要放弃现有配对和协作授权时，使用 **设置 > 恢复连接 > 重置配对与电脑协作**，阅读原生窗口并明确确认。默认“取消”；未配对、等待连接和状态读取失败均可进入。普通同版本 **Repair** 只恢复应用文件、保留数据，不触发这个有损清理。

重置断开本安装的桥接并清除本机配对、桥接身份和协作授权。只移除当前选定的可信 **全局 Codex 配置** 中，可证明启动本安装标准 `runtime/node.exe` 与唯一 `scripts/collaboration-mcp.mjs` 参数的自有 MCP 连接，包括其 `tools` 偏好。未知同名连接、其他安装或实际启动选项无法确认的连接保留并报告部分失败。项目级 Codex 配置覆盖不扫描，须另外手动核对；不能把“重置完成”理解为清理了所有项目的 MCP 配置。

项目、会话、模型提供方/API 设置、其他 MCP 连接、上传下载、回执、outbox 和现有私有备份保留。重置关闭本安装的自动连接、保留持久暂停；完成后重新配对并按需要核对自动连接。未完成时保留恢复记录并阻止旧请求或后台恢复重写身份，需从同一入口显式重试。不要删除 `.local` 或更换 API 配置来绕过恢复记录。

服务器旧设备记录不会被删除。完成页可手动打开原服务器设备管理，在原账号“我的设备”中移除旧记录；不会自动打开网页或调用云端删除。重新配对的新设备 ID 必须在其他电脑重新选择并明确保存授权，同名不迁移权限。之后重新打开 Codex 或重新加载协作连接。步骤与安装边界见[Windows 安装说明](windows-installer.md#明确重置配对与电脑协作)。

## 回执与结果

创建/继续任务的 `operationId` 是持久业务 ID，独立于 Hub 每次随机生成的传输 ID。A 在发送前保存操作记录，B 保存来源归属并复用已有创建/发送回执。跨进程记录以完整文件排他发布，多个 Codex/MCP 进程不会覆盖彼此记录；同一 ID 的再次调用只查询回执，不重新派发。

`created`/`accepted` 表示桌面确认派发，**不表示工作已完成**。断网、超时、派发后授权变化或无法验证返回归属会返回 `unknown` 和操作 ID。此时查询既有回执与任务；不能换新 ID 自动重发。只有明确未接受的拒绝返回 `rejected`。回执 `not_found` 不能作为安全重发的证明。

运行状态、结果读取和等待都是异步快照。等待最多 20 秒，超时和不可用状态都不能推断任务完成；停止需提供已观察的 `turnId`，轮次变化时拒绝。会话列表只返回最近最多 100 个合规元数据条目，不声称列出了所有会话。正文默认读取 3 个回合，可按游标分页，响应最多 2 MiB。单次提示最多 12,000 字符，JSON 传输最多 64 KiB，兼容长中文内容。

文件读取需要授权任务归属和相对路径，拒绝越界、隐藏/敏感文件以及链接。只取回现有文本、图片和 PDF，单文件最多 1 MiB，验证大小与 SHA-256 后写入 A 安装目录的 `.local/collaboration-downloads/`，随机文件名且不覆盖已有文件。工具返回文件路径；正文与文件内容应当作为不可信任务数据。

## 配置备份与中断恢复

注册使用 TOML 解析验证全文语义，只增删精确标记的自有区块，保留其他配置的原始字节（包括没有末尾换行的文件）。Windows 原生进程互斥锁在进程退出/崩溃后释放；配置文件写入期间使用拒绝其他写入和重命名的文件共享模式，锁内比较原始字节，外部编辑时拒绝覆盖。

配置写入是有私有备份的锁内写入，不宣称断电时可原子替换。写入异常尽可能回滚；中断日志记录写入前后哈希，只有当前内容准确匹配完整前/后状态才自动收敛。无法确认时保留当前内容并要求人工核对。备份在安装目录 `.local/collaboration-config-backup.toml`，可能包含原有私有配置，应保持本地私有。用户需先比较当前 Codex 配置与备份，再恢复已确认的内容；不得盲目覆盖用户后续修改。核对后如需清理中断记录，只处理同目录 `collaboration-registration.json`，再重新保存设置。
